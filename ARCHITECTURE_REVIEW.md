# Architecture Review
Generated: 2026-09-29T17:03:50.470Z

## Summary
A small, well-documented Vite/React mini-app with a clear components/pages/lib split, but scaffold-generated code has left two parallel domain models (contract.ts vs types.ts), duplicated SDK-guard/haptic/storage helpers, and several likely-dead components. The architecture is fundamentally sound, but there are conflicting type names, overlapping components (RewardGate/TossRewardAd, Amount/CountUp), and mixed import and error-handling conventions that should be consolidated.

## Issues
### Critical
- [consistency] Two incompatible domain models coexist. `contract.ts` defines UserInput/FireResult/Scenario (annual-based: annualExpense, annualIncome, targetAssets), while `types.ts` defines FireInput/FireResult/ScenarioResult (monthly-based: monthlyIncome, monthlyExpense). Both export a type named `FireResult` with different shapes; `fire.ts` has to alias one as `CalcFireResult`. `validation.ts` validates the contract `UserInput` (`validateUserInputFn`) as well as the types.ts fields (`validateInput` on 'monthlyIncome', etc.), so two validation paths exist. Pages use only the types.ts model, so the contract model looks like a leftover from packet generation. `contract.ts` also declares `RewardGateProps`, `AssetChartProps` and `ScenarioCompareProps`, which conflict with the actual component props. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/fire.ts, src/lib/validation.ts, src/lib/share.ts, src/lib/storage.ts, src/components/AssetChart.tsx, src/components/RewardGate.tsx / Fix: Pick one canonical domain model. If the monthly model is what the UI uses, adapt or remove the contract types (UserInput, Scenario, calcFireResult, validateUserInput) or move the adapter into a single `lib/domain` module. Rename the colliding `FireResult`. Delete the contract types that no component uses.

- [naming] Naming and import conventions are mixed. `BottomCTA.tsx` exports `SubmitFooter`/`ButtonStack`, and `StateView.tsx` exports `EmptyState`/`LoadingState` (file name ≠ export name). `contract.ts` uses lowercase type names (`calculateFireFn`) and mixed `annualX` vs `xxxRate` vs `xxxAssets`/`Asset` (`targetAssets` vs `targetAsset`, `annualReturn` vs `annualReturnRate`).
