## Summary
The codebase is a small, well-componentized React app (TDS/App-in-Toss mini-app) with decent separation between pages, presentational components, and lib helpers, and no genuine circular dependencies were found. However, it carries a critical split-brain domain model (a stale `contract.ts` spec that no longer matches the real `types.ts`/component shapes, including two incompatible types both named `FireResult`), several unused/dead exports, and repeated small duplications (haptics, duration formatting, numeric-text wrappers, SDK-guard boilerplate) that should be consolidated.

## Issues
### Critical
- [consistency] src/lib/contract.ts defines a full parallel domain model (UserInput, FireResult, Scenario, RewardGateProps, AssetChartProps, ScenarioCompareProps, etc.) that has diverged from the actually-implemented types in lib/types.ts and component props. Notably, 'FireResult' is defined twice with completely different, incompatible shapes ({isAchievable, yearsToFire, ...} vs {current, boosted, progressPercent, monthsSaved}), forcing an import alias (`FireResult as CalcFireResult`) in fire.ts just to avoid collision. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/fire.ts, src/components/RewardGate.tsx, src/components/ScenarioCompare.tsx, src/components/AssetChart.tsx / Fix: Treat contract.ts as historical design scaffolding only — either delete it, or update it to match the shipped types/props exactly and have implementations explicitly satisfy the contract types (e.g. `const calc: calculateFireFn = ...`) so drift is caught by the compiler.

### Suggestions
- [dead_code] src/components/TossPurchase.tsx and src/components/FloatingTabBar.tsx are not referenced by App.tsx, Home.tsx, or Result.tsx — they appear to be unused pre-built components shipped ahead of any screen that needs them. — Files: src/components/TossPurchase.tsx, src/components/FloatingTabBar.tsx / Fix: Either integrate them into a screen (e.g. wire FloatingTabBar if multi-tab nav is planned) or remove them until needed to avoid unmaintained dead surface area.
- [duplication] Amount.tsx and CountUp.tsx duplicate the same 'nowrap + tabular-nums span wrapping Paragraph.Text(formatNumber(value)+unit)' markup; CountUp only adds an animation layer on top. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Have CountUp render its animated value through a shared NumericText/Amount presentational core so the nowrap/tabular-nums styling lives in one place.
- [consistency] The 'guard SDK calls that throw outside the App-in-Toss WebView' pattern is hand-rolled with slightly different try/catch shapes in AdSlot, BottomCTA, RewardGate, TossPurchase, TossRewardAd, FloatingTabBar, and Home instead of a shared helper. — Files: src/components/AdSlot.tsx, src/components/BottomCTA.tsx, src/components/RewardGate.tsx, src/components/TossPurchase.tsx, src/components/TossRewardAd.tsx / Fix: Introduce a small `safeSdkCall(fn, onError?)` utility in lib to centralize the guard and reduce copy-pasted try/catch scaffolding.
- [structure] components/ is a flat directory mixing native-SDK wrappers (AdSlot, TossPurchase, TossRewardAd), generic UI primitives (Card, Amount, MiniBar, Sparkline), and page-layout shells (PageShell, ScreenScaffold, FloatingTabBar) with no subfolder grouping. — Files: src/components/AdSlot.tsx, src/components/Card.tsx, src/components/PageShell.tsx / Fix: As the component count grows, group into components/ads, components/ui, components/layout to make ownership and reuse boundaries clearer.
- [naming] Naming conventions are mostly consistent (PascalCase components, camelCase functions) but contract.ts introduces a distinct 'XxxFn' type-suffix convention (calculateFireFn, validateUserInputFn) not mirrored anywhere in the actual implementation code, and __TdsGallery.tsx uses a dunder file-name prefix unlike any other page file. — Files: src/lib/contract.ts, src/pages/__TdsGallery.tsx / Fix: Keep the dunder-prefix convention documented as 'dev-only route marker' and drop the 'Fn' suffix convention if contract.ts is reconciled with real code, so there's one naming scheme across the repo.
